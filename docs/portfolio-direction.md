# Основа личного портфолио

Дата исследования: 15 октября 2026 года. Статус: рабочее направление, не утверждённый дизайн.

## 1. Позиционирование

**Сергей Отческов. Архитектор брендов и цифровых систем.**

Эту формулировку нужно раскрыть через конкретную работу: как связаны образ бренда, структура сайта, пользовательский сценарий, интерфейс и реализация. Само слово «архитектор» не доказывает компетенцию.

Главная ценность портфолио — показать способность удерживать общий замысел и доводить его до работающего решения. В каждом проекте требуется различать личную работу, руководство командой и работу соавторов.

Предполагаемая аудитория: собственники компаний, руководители маркетинга и продукта, партнёры по сложным проектам. Это рабочая гипотеза для первой версии.

Связь с I’MON помогает объяснить организацию больших проектов. Однако личный сайт должен раскрывать решения и ответственность Сергея, а не повторять каталог услуг агентства.

### Черновик первого экрана

Имя: **Сергей Отческов**

Основное действие: **Смотреть проекты**. Контактное действие: **Обсудить задачу**.

Текст является редакционным предложением. Он не должен заменять конкретные доказательства в кейсах.

## 3. Пробел в доказательствах

Публичная подборка хорошо подтверждает веб-дизайн, анимацию и коммуникации событий. Чтобы уверенно раскрыть «цифровые системы», нужны кейсы с компонентами, состояниями интерфейса, содержанием, интеграциями и поддержкой после запуска.

Чтобы раскрыть «архитектор брендов», нужен хотя бы один разбор цепочки: исходная проблема → решение о позиционировании → визуальные принципы → носители. Если проект содержит только оформление, его следует так и описывать.

Недостаточно показать красивые финальные экраны. Нужны решения, ограничения и личная ответственность. Численные бизнес-результаты допустимы только с проверяемым основанием. Если метрик нет, результат описывается через реально запущенные функции и материалы.

## 4. Отбор и порядок

Для первой подборки из уже опубликованных работ предлагается:
1. Avito — коммуникация крупного события.
2. ORLA — премиальный веб-проект.
3. VK — сценарий участия и благотворительная платформа.
4. Rocket Group — структура нескольких направлений.
5. Haval — система презентационных и событийных материалов.

GAC и Six Senses входят в общий каталог. Окончательный порядок зависит от качества доступных обложек, полноты истории и подтверждённой личной роли. Свежий системный кейс должен войти в первые три позиции после подготовки материалов.

У каждой работы должна быть собственная причина присутствовать на главной. Два близких кейса недвижимости подряд ослабят ощущение широты.

## 5. Как использовать Uncoded

Проверены структура DOM, шрифты Instrument Serif и Geist, визуальный экран списка проектов и открытие меню. На первом экране часть белого текста и эффектов не отображается корректно в текущем исследовательском браузере. Полная визуальная и мобильная проверка остаётся открытой.

| Наблюдаемый приём | Адаптация |
| --- | --- |
| Крупная антиква и нейтральный гротеск | Выразительные заголовки с хорошей кириллицей; спокойные подписи |
| Свободное пространство и крупный масштаб | Один главный тезис на экран; ясные паузы между проектами |
| Строки проектов с годом, названием и направлением | Крупные названия и доступное превью; на телефоне обложка видна без наведения |
| Небольшое движущееся медиа в hero | Короткая подборка реальных работ, связанная с именем и позиционированием |
| Отдельные страницы работ | Самостоятельные истории с ролью автора, а не только внешние ссылки |
| Большое меню и заметный контакт | Прямой доступ к проектам, подходу, автору и связи |

Не переносить длинные абстрактные манифесты, шаблонные отзывы и показатели эффективности референса. Не превращать каталог работ в ряд одинаковых карточек.

Кириллицу необходимо проверить отдельно: визуально похожий латинский шрифт не гарантирует подходящие русские начертания. Конкретная пара шрифтов выбирается после пробного набора реальных заголовков и проверки лицензий.

### Движение

- Появление крупных строк и короткие переходы между разделами.
- Превью проекта по наведению и фокусу; постоянные превью на touch-устройствах.
- Обложка может переходить в страницу кейса, если это не задерживает навигацию.
- Основные тексты и ссылки доступны при сбое медиа и отключённых эффектах.
- При уменьшении движения в системных настройках остаётся спокойная версия.
- Сначала полноценная вёрстка, затем эффекты; WebGL используется только при ясной задаче.

## 6. Структура сайта

| Страница / раздел | Содержание и задача |
| --- | --- |
| Главная: первый экран | Имя, роль, понятное описание работы, реальные фрагменты проектов |
| Главная: избранное | Пять работ с разными доказательствами компетенции |
| Главная: подход | Как задача связывается с визуальным языком, сценарием и реализацией; примеры из проектов |
| Главная: об авторе | Короткая биография, личная роль, связь с I’MON, портрет |
| Главная: контакт | Telegram и почта; понятное предложение обсудить задачу |
| Все проекты | Полный каталог, простой выбор по направлению при достаточном количестве работ |
| Страница проекта | Контекст, роль, решения, система, реализация, результат, команда |
| Контакт | Прямые способы связи; сложная форма для первого выпуска не обязательна |

Подробную карьерную историю лучше раскрывать на отдельной странице автора после сверки дат. Главную не перегружать должностями, логотипами клиентов и списками программ.

## 7. Шаблон кейса

1. Название и одна фраза о задаче.
2. Сильная обложка или короткое видео реального проекта.
3. Заказчик / партнёр, период, роль Сергея, состав команды.
4. Проблема и ограничения.
5. Два-три ключевых решения с визуальными примерами.
6. Система: типографика, компоненты, сценарии, анимация или семейство носителей — по фактическому составу работы.
7. Что было реализовано и запущено.
8. Результаты с источниками; при отсутствии измерений — без чисел.
9. Благодарности, соавторы, внешняя ссылка, следующий проект.

Не заполнять один и тот же шаблон одинаковыми словами. Для события важны сцена и контент; для продукта — состояния и сценарии; для бренда — принципы и носители.

## 8. Факты, которые нужно сверить

- В источниках расходится длительность опыта. До проверки карьерной хронологии не публиковать общий стаж.
- Даты публикации в Dprofile не заменяют даты проектов.
- Авторские роли и вклад участников уточняются по каждому кейсу.
- Фото автора должно быть реальным и предоставленным/подтверждённым для сайта.
- Контакты по публичному Dprofile: cdo@imon.agency и Telegram imonsergei.
- Пока недоступны оригинальные медиа Dprofile, изображения не заменяются выдуманными кейсами.

## 9. Техническая основа будущей реализации

Контент отделён от интерфейса. Семь публичных работ описаны в `content/projects.json`. Незаполненные поля намеренно имеют значение `null`; все записи пока требуют редакционной подготовки.

Для сайта достаточно статически собираемых страниц с небольшим количеством клиентского JavaScript. Нужны собственные URL кейсов, метаданные, локальные оптимизированные изображения, адаптивные видео и доступное меню. CMS добавляется при реальной потребности регулярного редактирования.

Не использовать изображения с чужих CDN как постоянную зависимость. До публичного выпуска подготовить локальные ассеты с учётом авторства и командных кредитов.

Приёмка первой версии: корректные русские переносы, мобильная композиция, отсутствие горизонтального скролла, клавиатурная навигация, reduced motion, работа ссылок и независимость основного содержания от загрузки медиа.
